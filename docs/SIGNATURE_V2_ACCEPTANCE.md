# Visual signature v2 acceptance

Draw a mark with mouse, pen or touch, or type a supported name. Place multiple marks, change their page-relative position and size, remove them and use the shared undo/redo history. The default aspect ratio matches the 720×210 signature pad. Navigation retains ink and placement in the current session; starting over or replacing the source clears both. Typed marks use the pinned font's actual glyph paths, with explicit rejection of unsupported scripts/shaping and invisible-only names. The result review renders the exact downloadable PDF bytes.

This creates a visible appearance, not a certificate-backed signature. A conservative bounded PDF-object inspection rejects existing signature dictionaries, ByteRange entries or catalog permission signatures; it does not validate their cryptography. Empty unsigned signature fields remain allowed. The worker repeats the signed-source guard at export. Existing PDF text remains selectable; adding a visual mark does not securely erase underlying content.

Eight signature browser journeys cover typed placement/history/export, independently reopened PDF text and image objects, actual exported ink pixels, drawing and Back/Forward retention, empty/unsupported/invisible typed names, reset and replacement isolation, existing-signature rejection and narrow-page alignment. A ninth regression in the native-content suite verifies the same canvas-offset issue for existing source selection. Both offset tests failed by 29 pixels in fit-page mode before the fix. Three unit regressions verify signature policy, including inline signature dictionaries and empty unsigned fields.

Fresh review identified old ink being recaptured after reset/replacement and invisible typed marks creating transparent images. Both were reproduced failing and fixed. Further checking found the shared overlay offset on unusually narrow pages; both editing overlays now follow the canvas's exact size and position within the paper.

Local verification: 68 v2 Chromium journeys, 203 units, typecheck, lint, build and provenance verification. Published Chromium CI passed. Firefox/WebKit exposed an overly strict restoration assertion: PNG decoding/redrawing caused tiny RGB rounding differences, while every ink pixel's opacity and position were unchanged. The corrected browser test checks the full alpha geometry and exact original PNG preservation in the placed mark, rather than requiring a new canvas encoding to be byte-identical. All eight signature journeys pass locally after this test correction. New-head three-browser CI is still a separate required gate. Broader real-document, physical-device, assistive-technology and memory acceptance remains open. Legal certificate signing and cryptographic validation are not implemented by this adapter.
