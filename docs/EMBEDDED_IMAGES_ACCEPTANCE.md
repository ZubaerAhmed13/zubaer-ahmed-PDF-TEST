# Embedded-image extraction acceptance

The v2 adapter reuses the PDF.js extraction engine through a separate domain module. It exports decoded PNGs and a ZIP manifest; it does not render pages and call them extracted images, and it does not preserve original compressed streams or metadata.

Five real browser journeys verify shared/repeated image use on two pages (one record per page), native 2×2 dimensions and pixel equivalence, ZIP contents/manifest, individual PNG downloads, review navigation, text/vector-only failure, explicit skipped-mask disclosure, narrow one-bit grayscale pixels, cancellation before input reads finish, and rejection of an oversized native image. Leaving review revokes its image URL, verified by observing the real revoke API call after browser Back. Returning Forward creates a new URL. Revocation does not promise immediate eviction of an already decoded browser image: Firefox exposed this invalid assumption in the original reload-based test; Chromium and WebKit passed that test, while the Firefox run failed it twice. The test now checks the actual lifecycle contract across browsers.

Verification: all 47 current v2 Chromium journeys and 200 unit tests pass, as do typecheck, lint and provenance checks. Fresh three-browser CI is required on the published source. The screenshot check reserves each image's intrinsic aspect ratio and waits for image decoding before capture; real phone and screen-reader acceptance remains open.

The fresh review found three defects. Source dictionary dimensions are now checked before resolving decoded objects, and changed decoded dimensions fail instead of silently exporting a resized copy. The v2 caller disposes its mounted review during navigation while retaining result data for Forward. The retained legacy caller now labels extraction with skipped operations as incomplete. Native-size and URL-lifetime regressions failed before their fixes; the legacy warning copy is typechecked and remains outside current v2 browser navigation.

Bounds: 1,000 extracted/skipped records, 16 million pixels and 8,192 pixels per exported image dimension, 150 MB of encoded images, plus the common safe parser/input/page limits. Only one image preview URL is active at a time. PDF.js's inherited parser can decode images up to its shared 80 MP limit; the 16 MP limit is the export limit, not a claim about peak decoder memory.

Masks, grouped inline atlases, unavailable decoded objects and unsupported layouts are explicitly recorded as skipped raster operations. Vector artwork is not a raster image. Optimised repeated operators lacking original dimensions are conservatively skipped; the pinned `getOperatorList` API uses unoptimised OPLIST records, preserving original source dimensions and deduplication for ordinary repeated objects. Unsupported profiles/colour conversion and complex real-document fidelity still need a wider corpus. No original-stream-byte preservation is claimed.
