# R6 — repeatable jobs and finished exports

Goal: deliver v0.8.0 from the approved DocFlow roadmap, retaining all 29 tools, local documents, optional preference-only cloud sync and existing preservation/resource boundaries.
Approach: extend the existing workflow engine, batch UI, shared session and explicit export-link integration. No new processing service or document persistence.

## Task 1: portable recipes and preflight
Files: workflowEngine.ts, recipeTransfer.ts, workflowPreflight.ts, worker dispatch/types; tests/r6Workflows.test.ts.
Interfaces: version-1 `docflow-workflow` JSON envelope; whitelist recipe fields, reject future versions/oversize input; preserve v1 local presets. Preflight simulates page selections against each preceding step, checks cumulative crop geometry and reports actual per-step preservation consequences without editing a PDF. Add the already-tested single-output extract-pages operation and watermark page ranges. OCR retains its separate PDF/report review path until a workflow multi-output/report contract is defined.
Tests first: round-trip and deterministic execution, hostile JSON/unknown versions/oversize input, post-removal ranges, empty output, cumulative crop and signed-input warnings. Expected: fail before implementation, then pass.

## Task 2: repeat work UI
Files: workflowWorkspace.ts, batchWorkspace.ts, workflows.css, e2e/r6-workflows-exports.spec.ts.
Interfaces: dry-run summaries, stable naming, per-file original identity and immutable executed recipe/options for retries. Configuration edits never overwrite completed outputs; explicit Run starts a new job, retry uses original input and executed settings. Local import does not silently persist; export contains configuration only. Selected failed/cancelled retry, cancellation, ZIP and successes remain available.
Tests first: import/export/rerun, range failure without later mutation, duplicate names, edited-draft selected retry, cancellation and retained successes.

## Task 3: common export review and result handoff
Files: fileExport.ts, exportReview.ts, documentWorkspace.ts, workspaceRuntime.ts, export-review.css.
Interfaces: every output link retains its existing download; explicit export review adds filename, exact size/format, operation consequences and PDF review/compare/continue actions. Result events carry a specific File and optional original File, never a name lookup. Continue validates and adopts once, then opens reader; it never reruns the previous operation. Redaction history barrier and encrypted export-only behavior remain. Object URLs belong to the workspace and are revoked on cleanup.
Tests first: exact source/output pairing, multi-file names, rename/share consistency, direct and session handoff, original/result compare, redaction barrier, navigation cleanup and keyboard/mobile axe.

## Task 4: release
Update version, capabilities, release/help notes and production test selection. Run typecheck/lint/unit/build/audit/provenance and focused browser journeys; fresh whole-branch reviewer; fix important findings with regressions. Publish PR via the connected GitHub app, wait three-browser CI, merge and wait exact-main deployment/production checks. Independently reopen a live output and record exact build evidence.

Review focus: stale async import/preflight/ZIP completions, cancellation after worker handoff, changed draft vs executed recipe, source identity with equal names, retained result memory, path-like imported names, redacted history and encrypted output, page-relative selections after copy/crop operations, no recipes or content in cloud payloads.

Navigation editing/insert/replace are conditional roadmap items: R5 proved page-copy loses catalog structure, so they remain outside this release rather than advertising unproven preservation. Existing reader bookmarks/labels remain available.
