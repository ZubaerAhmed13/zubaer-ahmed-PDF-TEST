# OCR workspace acceptance — browser checks pending

The v2 OCR adapter uses the existing on-device Tesseract engine and same-origin English/German models. No PDF is uploaded by this adapter. It offers language/mixed-language recognition, selected pages, a one-to-thirty-page run limit, existing-text skipping, rotation/deskew/cleanup previews, cancellation, preserved settings, a searchable PDF, extracted-text download and review of the actual resulting PDF. Input metadata is capped at 40 MB before file reads. Unprocessed pages remain unchanged and are listed for retry from the original.

Corrections affect recognition input; the invisible text layer maps back onto the source scan. OCR may be wrong, is not tagged-document/accessibility certification, and rewrites invalidate existing digital signatures. The source stays unchanged. The small earlier engine corpus and hosted OCR checks do not establish broad accuracy for difficult scans.

A fresh reviewer reproduced two important issues before fixes: settings changes could leave stale correction previews, and a successful server-create response with a reset body could strand an unknown job. Preview generation and captured-option checks now reject stale images and clear displayed canvases. The server client retries the same canonical idempotency key after fetch or response-body failures. Its nine focused tests include consent before contact, scoped file links without auth headers, actual output-hash verification, delayed creation/cancellation, unconfirmed cancellation, upload-failure cleanup and uncertain-creation recovery. The reset-body and upload-failure regressions were observed failing before their fixes. An independent recheck found both review findings resolved.

The portable server client is a foundation; the OCR workspace does not yet expose server uploads. Its authenticated UI, provider/retention consent, recovery and browser-to-backend acceptance remain the next integration step. Normal backend uploads stay disabled and its synthetic acceptance-build gate has been switched off.

Four new browser cases cover real scan recognition, preserved unprocessed pages and settings, correction validation, and a deferred preview rejected after changing settings. The catalog entry test now follows the connected OCR workflow. Browser CI, current-head build/provenance and hosted interactive verification must pass before promotion.
