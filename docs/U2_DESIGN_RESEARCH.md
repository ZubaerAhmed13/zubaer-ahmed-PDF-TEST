# U2 — World-class interface: research, decisions and acceptance

Date: 19 October 2026  
Scope: **UI and interaction first.** A feature request is not a claim of shipping a conversion engine.

## User reference
Seven supplied screenshots show iLovePDF's categorized tool catalogue, one-purpose upload page, side-by-side page editing/options, a document viewer with form controls, reorderable merge cards with zoom, a full-page preview, and visual page deletion. Desired result: the same understandable sequence with a calmer visual identity, faster repeat tasks, stronger mobile layout and clearer editing feedback.

## Sources and learnings
- iLovePDF official user guide: select a specific operation first, rearrange thumbnails before merging, select page thumbnails for removal, then create the output. https://www.ilovepdf.com/help/documentation
- Adobe Acrobat on the web, Organize pages (2026-04-01): page thumbnails, direct rotate/delete/insert actions, and undo are core workspace affordances. https://helpx.adobe.com/acrobat/web/edit-pdfs/organize-documents/organize-pages.html
- PDF24 mobile/installed-app explanation: consistent tools across desktop and mobile, with realistic disclosure of server-backed operations. https://tools.pdf24.org/en/install-app
- Nielsen Norman Group, progressive disclosure: reserve second-level panels for secondary controls, keeping the primary action apparent. https://www.nngroup.com/videos/progressive-disclosure/
- W3C WCAG 2.2: minimum target sizes, visible focus and single-pointer alternatives to drag movements. https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/ and https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements

## Design decisions in U2
1. **One visual language.** New design tokens for deep ink, violet primary action, pale canvas, rounded cards and spacious but efficient layouts.
2. **Task-first discovery.** Search and categories remain central; shortcut chips open real implemented tools and require no new page or backend.
3. **Scannable, honest cards.** Categorical icon colour, real operation description, disclosure of quality/processing, explicit open button, favourite control.
4. **Single-stage focus.** Upload screen emphasises file selection; work screen keeps actual PDF tool actions; dedicated result screen highlights the real generated export.
5. **Adapt across breakpoints.** Four-column desktop catalogue, three/two-column intermediate sizes, compact phone cards with a one-column escape hatch for narrow devices.
6. **Keep powerful interactions.** Direct PDF editor, preview, merge/order, forms and mobile files/options panels remain available; no mutation of the processing layer.
7. **Accessible navigation.** Category tabs implement arrow/Home/End and roving tab index; focus visibility and minimum touch targets are enhanced.
8. **Reduced-motion respect.** Hover movements and transitions are removed for reduced-motion users.

## Next UI iterations (not shipped in U2)
- **U3 workspace pattern library:** create consistent page-thumbnail cards with clear select, move, rotate, preview and remove controls across native tools. Verify non-drag alternatives and selected ranges by operation.
- **U4 precision editor:** shared top toolbar, local mini inspector, fitting/zoom shortcuts, undo/redo state across visual editing; maintain honest feature support.
- **U5 mobile experience:** test 320/375/390/430 widths on actual Android/iOS, bottom sheet behaviour, keyboard occlusion, reachability, input selection and touch zoom.
- **U6 result comprehension:** show action summary and compare/review affordances for supported tools; preserve exact generated bytes, filenames, ZIP and warnings.
- **U7 usability study:** six realistic tasks (merge, split, reorder, delete, fill form, edit), first-attempt success and error recovery, with desktop/mobile users.

## Feature parity work *after* UI foundation
Screenshot requests to add Office to/from PDF, HTML to PDF, PDF/A, AI summary, translation and Markdown require separate documented capability decisions, server-side processing where quality measurably improves, secure handling and test datasets. Do not label the UI complete while engines are missing.

## Quantified UX acceptance targets (goals, not measured results)
- 90% of first-time participants complete the six-task set without assistance.
- Median time-to-first-file-selection ≤10s on desktop, ≤15s mobile for a known target operation.
- No horizontal overflow from 320–1440 CSS px.
- All important actions at least 44×44 CSS px where practical; WCAG 2.2 AA target compliance.
- No PDF-engine or output-format regression; maintain test baseline and honest warnings.
- Compare against the U1 baseline using the same task scripts, device class and test files; do not claim a 2× improvement without measured evidence.
