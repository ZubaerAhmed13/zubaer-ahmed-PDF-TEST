# Workflow and batch v2 acceptance

Workflow has a labelled step editor for eight supported operations, up to eight steps, explicit add/remove/up/down actions and ordinary fields. Batch uses the same editor with one of rotate, page numbers, watermark or image optimisation. Each queued original can be previewed. Recipes can be imported/exported and explicitly saved/deleted on the device; document bytes never enter recipe storage. Initial and loaded built-ins are normalized to show their complete effective settings.

The new coordinator reuses the existing validated recipe, preflight and chaining engines. Metadata limits are checked before reading: 20 PDFs, 50 MB each, 150 MB combined. Processing reads one original at a time and runs one worker at a time. Each output is capped at 50 MB and completed PDFs at 150 MB combined. Check files reports cumulative page counts and preservation warnings without changing the source. Every execution repeats preflight. An independent file failure does not stop the queue. Cancellation retains completed outputs, and retry runs only failed/cancelled originals with their prior validated settings, even if current controls have changed or become invalid.

Results show each file's actual state and preflight consequences. Only completed PDFs are downloadable; selecting a result renders those exact bytes. Output names are sanitized and unique. ZIP packaging is explicit, uses completed outputs only and supports at most 75 MB of source PDFs. Larger completed queues remain individually downloadable. This is an encoded-byte budget, not a certified heap-usage or physical-device capacity claim.

Porting revealed that workflow JPEG quality used an option name ignored by the image engine. A failing unit probe confirmed this. Quality is now mapped to the actual worker option, with an effective 50–95% range and maximum image dimension of 900–5000 px. Previously saved quality values of 35–100 are accepted and normalized to the engine's effective range. Unsupported image encodings remain unchanged. A browser test reopens the exported PDF and verifies an actual 1800-pixel image was downsampled to 1000 pixels.

Eight browser journeys verify chained extraction/rotation and original selectable text, read-only cumulative preflight failure/recovery, damaged-file isolation, unique ZIP entries reopened as PDFs, partial cancellation and original-settings retry, rejection of oversized additions before reading, phone-width step/preset/import/export flows, compression settings and stale-import/focus behavior. Seven orchestration units cover default controls, metadata limits, sequential reads/workers, failure isolation, immutable/invalid-current-settings retry, cancellation and checked-file retry eligibility. Existing workflow-unit coverage also verifies the compression-option mapping.

Fresh read-only review reproduced editor context/focus loss and a slow import overwriting newer settings. Browser regressions failed first on operation focus, then on stale import, and pass after fixes. Repaints now preserve expanded recipe controls, preset selection and focus; revision guards discard stale imports. The reviewer independently rechecked Save, operation changes and imports racing presets, edits, execution and newer imports, with no remaining important defects in those fixes. A checked-file retry regression also failed before the coordinator's eligibility fix.

Local verification passed: all 76 current v2 Chromium journeys, 211 units, typecheck, lint, build and provenance. Published-head Chromium, Firefox and WebKit CI remains required before promotion. Full legacy parity, broader document fidelity, memory stress, real devices and manual assistive-technology acceptance remain open. Page-copy steps lose document structures; crop does not redact; rewrites invalidate digital signatures and may preserve active content. No server processing or upload is enabled by this stage.
